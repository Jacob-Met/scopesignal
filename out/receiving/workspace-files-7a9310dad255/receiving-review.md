## Execution and limits

The run used native Chromium 153.0.8010.47 from Snap and Node v22.22.1 for the receiver, with an isolated profile and loopback HTTP server. This is browser acceptance of the application, separate from the producer's native Node test suite. Real file reads and downloads were used; only the explicitly declared read-delay/read-failure and download-preparation controls were synthetic. No provider, upload, live payment action or user browser session was involved. The inherited Google Fonts requests were blocked and recorded. No other external request, non-GET request, JavaScript exception or CDP error occurred in the successful run.

To reproduce, retrieve the candidate's exact browser leaves listed in `candidate-manifest.json`, retain the receiver beside `frozen-fixtures/` and its manifests, and use an existing native Chromium installation:

```sh
SCOPE_RECEIVING_PROFILE_ROOT=/absolute/unique/writable/profile-root \
SCOPE_RECEIVING_CHROMIUM=/absolute/path/to/chromium \
node workspace-receiver-v4.mjs candidate /absolute/source \
  /absolute/candidate-manifest.json /absolute/new-evidence-directory
```

For Snap Chromium, place selected files, evidence and the profile within accessible visible home paths. To regenerate the independent fixtures, place the exact baseline source identified by `baseline-manifest.json` under `baseline/` before running `freeze-fixtures.mjs`. Copied application source, browser executables and transport archives are deliberately excluded from the publication packet; their exact public identities and all original receiving inputs and outputs are retained.
